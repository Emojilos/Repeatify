# PRD: Платформа подготовки к ЕГЭ по профильной математике

**Версия:** 1.0
**Дата:** 2026-03-09
**Статус:** Draft

---

## 1. Обзор продукта и цели

### 1.1 Описание
Веб-платформа для подготовки к ЕГЭ по профильной математике 2026, построенная на принципах научно обоснованных методов обучения: Spaced Repetition System (SRS), методологии FIRe (Frameworks, Inquiry, Relationships, Elaboration), Interleaved Practice, Active Recall и Dual Coding.

### 1.2 Проблема
Существующие платформы подготовки к ЕГЭ (Решу ЕГЭ, Foxford, СДАМ ГИА) используют устаревший подход блочного обучения: ученик решает однотипные задачи блоками, что создаёт иллюзию компетентности, но не формирует долговременную память и гибкость мышления. Ни одна из популярных платформ не интегрирует SRS-алгоритмы и методологию FIRe для системного формирования математического понимания.

### 1.3 Ключевое ценностное предложение
Единственная платформа подготовки к ЕГЭ по математике, которая:
- Использует алгоритм интервального повторения для автоматического планирования повторений
- Реализует пошаговый FIRe-flow для глубокого понимания каждой темы
- Применяет Interleaving (чередование тем) в тренировочных сессиях
- Адаптирует план подготовки под оставшееся время до экзамена
- Мотивирует через систему XP, уровней и стриков

### 1.4 Целевая аудитория
- **Первичная (MVP):** Личное использование автором проекта
- **Вторичная (масштабирование):** Выпускники 10–11 классов, готовящиеся к ЕГЭ по профильной математике
- **Перспективная:** Репетиторы, использующие платформу как инструмент для учеников

### 1.5 Метрики успеха
- Ежедневное использование платформы (streak consistency > 80%)
- Рост процента правильных ответов по каждому типу заданий за 30 дней
- Время решения задач Части 1 < 5 минут на задачу
- Покрытие всех 19 типов заданий контентом (теория + задания)

## 3. Основные функции и функциональность

### 3.1 Режим «Обучение» — FIRe Flow

Пошаговый guided flow для изучения новой темы. Каждая тема проходит через 4 этапа методологии FIRe.

**Пользовательский сценарий:**

1. Ученик выбирает тему (например, «Производная. Геометрический смысл» — задание №8)
2. **Этап F — Framework (Фреймворк):**
   - Система показывает концептуальную карту темы: место производной в анализе, связь с пределами, геометрическая интерпретация
   - Визуальная схема (mind map) связей данной темы с другими разделами
   - Ключевые формулы с LaTeX-рендерингом
   - Acceptance criteria: ученик видит интерактивную карту темы с кликабельными узлами, каждый узел раскрывает краткое описание
3. **Этап I — Inquiry (Исследование):**
   - Система задаёт серию исследовательских вопросов: «Что происходит с производной в точке экстремума?», «Почему производная константы равна нулю?»
   - Ученик формулирует ответ (текстовое поле для размышлений, не оценивается автоматически)
   - После ответа показывается эталонное объяснение
   - Acceptance criteria: минимум 3 исследовательских вопроса на тему, ответ ученика сохраняется для рефлексии
4. **Этап R — Relationships (Связи):**
   - Интерактивная визуализация связей текущей темы с другими: «Производная ↔ Касательная ↔ Угловой коэффициент ↔ Тригонометрия»
   - Ученику предлагается найти и назвать дополнительные связи
   - Acceptance criteria: граф связей с минимум 4 связанными темами, возможность добавления пользовательских связей
5. **Этап E — Elaboration (Детализация / Техника Фейнмана):**
   - Ученику предлагается объяснить тему «простым языком» (текстовое поле)
   - Чек-лист ключевых пунктов, которые должны быть в объяснении
   - Acceptance criteria: чек-лист из 3–5 пунктов, ученик отмечает покрытые пункты, прогресс сохраняется

**Данные, создаваемые после прохождения FIRe-flow:**
- Тема помечается как «изучена» в профиле ученика
- Создаются SRS-карточки по ключевым концептам темы (автоматически)
- Записывается дата изучения для планирования повторений

### 3.2 Режим «Тренировка» — Адаптивная SRS-сессия

Система автоматически подбирает задания на основе алгоритма интервального повторения с элементами интерливинга.

**Алгоритм подбора заданий:**

```
1. Рассчитать для каждого задания в пуле:
   - days_since_last_review: дней с последнего решения
   - current_interval: текущий интервал повторения
   - ease_factor: коэффициент лёгкости (начальный 2.5)
   - urgency_score: days_since_last_review / current_interval

2. Отфильтровать задания, готовые к повторению (urgency_score >= 1.0)

3. Применить Interleaving:
   - Не более 2 подряд заданий из одной темы
   - Приоритет смешивания родственных тем (например, планиметрия + стереометрия)

4. Учесть время до экзамена (exam_countdown_factor):
   - Если < 30 дней: сжать интервалы на 40%, приоритет слабым темам
   - Если 30–90 дней: стандартные интервалы
   - Если > 90 дней: можно удлинять интервалы, фокус на глубоком понимании

5. Сформировать сессию из 10–20 заданий
```

**SRS-параметры (модифицированный SM-2):**

| Самооценка | Описание | Действие |
|------------|----------|----------|
| `again` | Не помню / Ошибка | interval = 1 день, ease_factor -= 0.2 |
| `hard` | С большим трудом | interval *= 1.2, ease_factor -= 0.15 |
| `good` | Вспомнил нормально | interval *= ease_factor |
| `easy` | Мгновенно, без усилий | interval *= ease_factor * 1.3, ease_factor += 0.15 |

**Для заданий Части 1:** ученик вводит числовой ответ → система проверяет автоматически → показывает кнопки самооценки сложности (again/hard/good/easy).

**Для заданий Части 2:** ученик решает на бумаге → нажимает «Показать решение» → сравнивает с эталоном → оценивает себя (again/hard/good/easy).

**Acceptance criteria:**
- Сессия формируется за < 500ms
- Каждое задание показывает номер в сессии, тип задания ЕГЭ, сложность
- После сессии — сводка: решено, правильно, по темам, XP заработано
- История всех сессий сохраняется

### 3.3 Система учёта времени до экзамена

**При регистрации / в настройках:**
- Ученик указывает дату экзамена (по умолчанию: дата ЕГЭ по математике 2026)
- Ученик указывает целевой балл (тестовый, 27–100)

**Dashboard показывает:**
- Обратный отсчёт (дней до экзамена)
- Прогресс по темам с учётом целевого балла
- Рекомендации по темпу: «Вам нужно изучать 2 новые темы в неделю и проходить 15 SRS-карточек в день»
- Предупреждения: «До экзамена 14 дней. Тема "Стереометрия" (№14, 3 балла) не изучена. Рекомендуем сфокусироваться.»

**Адаптация SRS-интервалов:**
- `exam_days_remaining < 14`: интервалы сжимаются до 60% от стандартных, приоритет — повторение изученного
- `exam_days_remaining < 30`: интервалы сжимаются до 75%, баланс нового и повторения
- `exam_days_remaining < 90`: стандартные интервалы, фокус на изучении новых тем
- `exam_days_remaining >= 90`: удлинённые интервалы, глубокое изучение через FIRe

**Приоритизация тем по ROI (Return on Investment):**
```
topic_priority = (max_points / estimated_study_hours) * weakness_score * exam_urgency
```
Где:
- `max_points` — максимальный балл за задание (1–4)
- `estimated_study_hours` — оценка времени на изучение темы
- `weakness_score` — насколько слабо ученик знает тему (0–1, на основе истории ответов)
- `exam_urgency` — коэффициент срочности (растёт по мере приближения экзамена)

### 3.4 Система прогресса и мотивации

**XP (Experience Points):**
- Правильный ответ Часть 1: +10 XP
- Правильный ответ Часть 2 (самооценка «good»/«easy»): +25 XP
- Завершение FIRe-flow по теме: +50 XP
- Завершение SRS-сессии целиком: +30 XP (бонус)
- Бонус за серию правильных ответов (3+ подряд): +5 XP за каждый следующий

**Уровни:**

| Уровень | Название | XP для достижения |
|---------|----------|------------------|
| 1 | Новичок | 0 |
| 2 | Ученик | 100 |
| 3 | Практикант | 300 |
| 4 | Знаток | 700 |
| 5 | Эксперт | 1500 |
| 6 | Мастер | 3000 |
| 7 | Гуру | 6000 |
| 8 | Стобалльник | 12000 |

**Стрики (Streaks):**
- Ежедневный стрик: засчитывается при завершении хотя бы 1 SRS-сессии ИЛИ 1 FIRe-flow в день
- Визуальный календарь активности (heatmap, как на GitHub)
- Milestone стриков: 7 дней, 30 дней, 60 дней, 100 дней → бонус XP

**Acceptance criteria:**
- XP и уровень отображаются в header на каждой странице
- Анимация при получении XP и при повышении уровня
- Календарь стриков на странице профиля
- Данные стриков не сбрасываются при пропуске (нет «наказания», стрик просто прерывается и начинается заново)

### 3.5 Отслеживание прогресса и «Карта пробелов»

**Dashboard содержит:**
- Общий прогресс: % изученных тем, % решённых заданий
- Heatmap по типам заданий (1–19): цветовая шкала от красного (слабо) до зелёного (уверенно)
- График динамики правильных ответов за последние 7 / 30 дней
- Текущий SRS-стек: сколько карточек на повторение сегодня

**Карта пробелов (Gap Map):**
Автоматически генерируемая таблица на основе истории ответов:

| Поле | Описание |
|------|----------|
| `task_number` | Номер задания ЕГЭ (1–19) |
| `topic` | Конкретная подтема |
| `error_type` | Теоретическая / Практическая / Поведенческая |
| `error_count` | Количество ошибок за последние 30 дней |
| `last_error_date` | Дата последней ошибки |
| `strength` | Текущая «сила» темы (0–100%, рассчитывается из SRS-данных) |
| `recommended_action` | Автоматическая рекомендация: «Повторить теорию» / «Решить 5 задач» / «Пройти FIRe-flow заново» |

**Acceptance criteria:**
- Dashboard загружается за < 1 секунду
- Карта пробелов обновляется после каждой сессии
- Можно отфильтровать по типу ошибки, номеру задания, силе темы

### 3.6 Теоретический контент

**Структура материала по каждой теме:**
- Краткая теория с формулами (LaTeX-рендеринг через KaTeX)
- Ключевые теоремы и определения
- Визуальные пояснения (графики, схемы) — Dual Coding
- Типовые методы решения с примерами
- Частые ошибки и ловушки
- Связи с другими темами (для этапа R в FIRe)

**Формат хранения контента:** Markdown с LaTeX-вставками, хранится в Supabase (таблица `theory_content`).

## 4. Технический стек

### 4.1 Архитектура

```
┌─────────────────────┐     HTTPS/REST API     ┌──────────────────┐
│   Frontend (SPA)    │ ◄──────────────────────►│  Backend (API)   │
│   Vite + React      │                         │  FastAPI         │
│   GitHub Pages      │                         │  Render          │
│   KaTeX             │                         │                  │
└─────────────────────┘                         └────────┬─────────┘
                                                         │
                                                         │ Supabase Client
                                                         ▼
                                                ┌──────────────────┐
                                                │    Supabase      │
                                                │  PostgreSQL DB   │
                                                │  Auth            │
                                                │  Storage         │
                                                └──────────────────┘
```

### 4.2 Frontend

| Решение | Обоснование |
|---------|-------------|
| **Vite + React 18** | Быстрая сборка, HMR, простой статический экспорт для GitHub Pages |
| **React Router v6** | Client-side routing (hash-based для GitHub Pages) |
| **KaTeX** | Рендеринг LaTeX-формул (быстрее MathJax, достаточен для математики ЕГЭ) |
| **Tailwind CSS** | Утилитарный CSS, быстрая стилизация без написания кастомных стилей |
| **Recharts** | Графики прогресса на dashboard |
| **Zustand** | Лёгкий state management (проще Redux для данного масштаба) |

**Деплой на GitHub Pages:**
- `vite build` → статические файлы в `dist/`
- GitHub Actions для CI/CD: push в `main` → автобилд → деплой в `gh-pages` branch
- Hash-based routing (`HashRouter`) для корректной работы SPA на GitHub Pages

### 4.3 Backend

| Решение | Обоснование |
|---------|-------------|
| **Python 3.11+ / FastAPI** | Асинхронный, быстрый, автогенерация OpenAPI-документации |
| **Supabase Python Client** | Прямая работа с Supabase DB и Auth |
| **Pydantic v2** | Валидация данных на API-уровне |
| **Uvicorn** | ASGI-сервер для FastAPI |

**Деплой на Render:**
- Web Service (Free tier для MVP)
- Auto-deploy из GitHub репозитория
- Переменные окружения: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `JWT_SECRET`

**Важно:** Render Free tier усыпляет сервис после 15 минут неактивности. Первый запрос после сна занимает ~30 секунд. Для MVP это допустимо. При масштабировании — переход на Starter ($7/мес).

### 4.4 База данных (Supabase)

| Компонент | Использование |
|-----------|---------------|
| **PostgreSQL** | Основное хранилище: пользователи, задания, прогресс, SRS-данные |
| **Supabase Auth** | Email + пароль регистрация, JWT-токены, сессии |
| **Supabase Storage** | Изображения к заданиям (графики, чертежи) |
| **Row Level Security** | Пользователь видит только свои данные прогресса |

## 5. Концептуальная модель данных

### 5.1 Основные таблицы

**`users`** (расширение Supabase Auth)
```
id: UUID (PK, from Supabase Auth)
display_name: VARCHAR(100)
exam_date: DATE
target_score: INTEGER (27–100)
current_xp: INTEGER (default 0)
current_level: INTEGER (default 1)
current_streak: INTEGER (default 0)
longest_streak: INTEGER (default 0)
last_activity_date: DATE
created_at: TIMESTAMPTZ
```

**`topics`**
```
id: UUID (PK)
task_number: INTEGER (1–19) — номер задания ЕГЭ
title: VARCHAR(200)
description: TEXT
parent_topic_id: UUID (FK → topics.id, nullable) — для подтем
difficulty_level: ENUM('basic', 'medium', 'hard')
max_points: INTEGER — максимальный балл за задание ЕГЭ
estimated_study_hours: FLOAT
order_index: INTEGER — порядок отображения
```

**`theory_content`**
```
id: UUID (PK)
topic_id: UUID (FK → topics.id)
content_type: ENUM('framework', 'inquiry', 'relationships', 'elaboration', 'summary')
content_markdown: TEXT — Markdown с LaTeX
visual_assets: JSONB — ссылки на изображения/схемы в Supabase Storage
order_index: INTEGER
```

**`problems`**
```
id: UUID (PK)
topic_id: UUID (FK → topics.id)
task_number: INTEGER (1–19)
difficulty: ENUM('basic', 'medium', 'hard', 'olympiad')
problem_text: TEXT — условие задачи (Markdown + LaTeX)
problem_images: JSONB — массив URL изображений
correct_answer: VARCHAR(50) — числовой ответ для автопроверки
answer_tolerance: FLOAT (default 0) — допустимая погрешность
solution_markdown: TEXT — пошаговое эталонное решение
solution_images: JSONB
hints: JSONB — массив подсказок по уровням
source: VARCHAR(200) — источник (ФИПИ, Ященко и т.д.)

```

**`user_problem_attempts`**
```
id: UUID (PK)
user_id: UUID (FK → users.id)
problem_id: UUID (FK → problems.id)
user_answer: VARCHAR(50)
is_correct: BOOLEAN
self_assessment: ENUM('again', 'hard', 'good', 'easy')
time_spent_seconds: INTEGER
attempted_at: TIMESTAMPTZ
```

**`srs_cards`**
```
id: UUID (PK)
```

### 5.3 Row Level Security (RLS)

Все таблицы с `user_id` имеют RLS-политики:
```sql
CREATE POLICY "Users can only access own data"
ON user_problem_attempts FOR ALL
USING (auth.uid() = user_id);
```

Таблицы `topics`, `theory_content`, `problems`, `topic_relationships` — доступны для чтения всем авторизованным пользователям.

## 8. Безопасность

### 8.1 Аутентификация
- Supabase Auth (email + пароль)
- JWT-токены с expiration (1 час access, 7 дней refresh)
- Хеширование паролей — управляется Supabase (bcrypt)
- Rate limiting на auth-эндпоинтах: 5 попыток / минута

### 8.2 Авторизация
- Row Level Security (RLS) на всех пользовательских таблицах в Supabase
- Backend валидирует JWT на каждом запросе через middleware
- Админские эндпоинты (добавление заданий) защищены отдельной ролью

### 8.3 Защита данных
- HTTPS everywhere (GitHub Pages и Render предоставляют TLS бесплатно)
- CORS: только домен GitHub Pages frontend
- Переменные окружения для всех секретов (никогда в коде)
- Supabase service key используется только на backend, никогда на frontend

### 8.4 Защита контента (на будущее)
- При масштабировании: контент заданий доступен только авторизованным пользователям
- Rate limiting на API: 100 запросов / минута на пользователя

| Проблема | Риск | Решение |
|----------|------|---------|
| **Render Free tier спит после 15 мин** | Первый запрос ~30 сек, плохой UX | MVP: допустимо. Масштабирование: Render Starter ($7/мес) или cron-пинг каждые 14 мин |
| **Наполнение контентом — bottleneck** | 19 типов × теория + задания = огромный объём работы | Начать с 5 приоритетных тем. Использовать открытый банк ФИПИ. Постепенно расширять |
| **Качество SRS-алгоритма** | SM-2 может быть неоптимален для математических задач | Начать с SM-2, собирать данные. Итеративно калибровать `ease_factor` и интервалы на основе статистики |
| **LaTeX-рендеринг тяжёлых формул** | Задания №14, №17, №18 могут требовать сложных конструкций | KaTeX покрывает 95% математики ЕГЭ. Для оставшихся 5% — изображения |
| **Проверка Части 2** | Автоматическая проверка развёрнутых ответов невозможна | Самопроверка по эталону + самооценка SRS. В будущем: фото решения + AI-оценка |
| **GitHub Pages SPA routing** | Прямые ссылки на вложенные routes возвращают 404 | HashRouter в React Router ИЛИ 404.html fallback hack |
| **Supabase Free tier лимиты** | 500 MB БД, 1 GB Storage, 50K auth users/месяц | Для личного использования — более чем достаточно. При масштабировании — Pro ($25/мес) |
| **Формулы в мобильном виде** | KaTeX формулы могут не помещаться на маленький экран | MVP desktop-only. Для будущего мобильного — горизонтальный скролл внутри формул |

## Приложение A: Методологическая база

Данный PRD опирается на исследовательский документ «Архитектура когнитивной оптимизации и научно обоснованные стратегии подготовки к ЕГЭ по профильной математике», в котором описаны:

- **Active Recall** — активное припоминание вместо пассивного перечитывания. Реализуется через решение задач без подсказок и SRS-карточки.
- **Spaced Repetition (SRS)** — интервальное повторение по алгоритму SM-2 с адаптацией интервалов. Борьба с кривой забывания Эббингауза.
- **Interleaving** — чередование тем в тренировочных сессиях для развития навыка классификации задач (критично для ЕГЭ, где задания идут без указания темы).
- **FIRe (Frameworks, Inquiry, Relationships, Elaboration)** — методология Dr. Justin Sung для высшего порядка мышления: построение концептуальных каркасов, исследовательское вопрошание, нелинейное связывание тем, детализация через технику Фейнмана.
- **Dual Coding** — параллельное использование визуального и вербального каналов (формулы + графики + схемы).
- **Карта пробелов (Gap Map)** — классификация ошибок на теоретические, практические и поведенческие с автоматической рекомендацией действий.
